Dojang 인증으로
ZK proof를 생성하고 검증하는 구조

ZKProofport는 인증 데이터를 발급하는 계층과 이를 사용하는 dApp 사이에서 필요한 사실만 영지식 증명으로 전달합니다. dApp은 원본 인증 데이터를 받거나 보관할 필요가 없습니다.

MVP 확인 구현 자료

01 / PROBLEM

Dojang 인증 조회 과정의
지갑 프라이버시 문제

Dojang은 신뢰할 수 있는 오프체인 데이터를 온체인 인증 데이터로 연결합니다. 그러나 dApp이 인증 데이터가 발급된 원본 지갑 주소를 직접 조회하면, 해당 지갑의 온체인 활동 기록과 신원 인증 상태가 결합될 수 있습니다. Verified Balance처럼 수치가 포함된 데이터는 서비스에 필요 이상의 민감 정보를 노출할 수 있습니다.

ZKProofport는 Dojang이 제공하는 신뢰를 그대로 활용하면서, dApp에는 조건을 판단하는 데 필요한 최소한의 증명 결과만 전달합니다.

02 / ARCHITECTURE

Dojang → ZKProofport → GIWA verifier

TRUST SOURCE Dojang / EAS
→
USER DEVICE ZKProofport
→
PROOF SYSTEM Noir · mopro
→
GIWA CHAIN HonkVerifier
  1. 01dApp이 필요한 검증 항목과 서비스별 scope를 요청합니다.
  2. 02사용자 기기에서 지갑 소유권과 attestation의 유효성을 확인합니다.
  3. 03Noir 서킷이 private inputs를 사용해 UltraHonk proof를 생성합니다.
  4. 04GIWA verifier가 proof와 public inputs만으로 유효성을 검증합니다.

03 / PRIVACY

dApp이 검증하는 결과와
dApp에 공개되지 않는 원본 정보

dApp에 전달되는 정보

  • 요청한 조건의 충족 여부
  • 서비스별 scope
  • 중복 사용을 막는 scope-bound nullifier
  • proof의 수학적 유효성

dApp에 전달되지 않는 정보

  • Dojang 데이터가 발급된 원본 지갑 주소
  • raw attestation transaction
  • 지갑 서명과 public key
  • 개인 신원과 정확한 자산 정보

APPLICATION EXAMPLES

KYC 인증 사용자 대상 혜택 원본 지갑 주소를 공개하지 않고 에어드랍, 온보딩 보상, 파트너 혜택 또는 우선 참여권을 제공할 수 있습니다.
잔고 조건 기반 등급과 혜택 Verified Balance 서킷을 추가하면 정확한 잔고 대신 특정 시점의 자산 기준 충족 여부만 확인해 등급, 수수료 혜택 또는 proof-of-funds에 활용할 수 있습니다.
프라이빗 참여와 접근 제어 원본 지갑의 활동 내역을 공개하지 않고 이벤트, 민팅, 인증 커뮤니티, 거버넌스 등의 참여 조건과 scope별 중복 참여를 확인할 수 있습니다.

동일한 구조는 연령, 국가, 지역, 조직 소속 등 다른 credential 조건에도 확장할 수 있습니다.

04 / CIRCUIT

GIWA attestation 검증 서킷

  • 01사용자의 public key에서 주소를 유도하고 지갑 서명을 검증합니다.
  • 02attestation transaction을 파싱하고 허용된 발급자의 서명을 확인합니다.
  • 03transaction의 대상 컨트랙트와 호출 데이터가 증명 대상 지갑과 일치하는지 확인합니다.
  • 04사용자와 서비스 scope를 결합한 nullifier를 계산해 서비스 간 추적을 어렵게 하고 중복 사용을 막습니다.

06 / BOUNDARY

GASOK(Production) 단계: 공식 Dojang 데이터 연동

현재 PoC는 Dojang 발급 이후의 ZK 증명 파이프라인을 검증합니다. 공식 Dojang Verified Address는 사용자가 KYC를 완료한 뒤 업비트가 발급하는 운영 데이터입니다. 현재 PoC에서는 발급 단계에 테스트 attester를 적용해 서킷·모바일 증명·verifier 흐름 전반을 검증했습니다. Production 단계에서 공식 Dojang 데이터의 발급자 주소, schema, 인증 정책을 연동할 계획입니다.

07 / ROADMAP

GIWA Wallet 네이티브 통합 로드맵

초기에는 ZKProofport 앱과 SDK를 통해 빠르게 dApp 연동을 지원합니다. 공식 Dojang 데이터 연동 이후에는 증명 요청·동의·생성 과정을 GIWA Wallet에 네이티브로 통합합니다. dApp은 같은 요청 규격을 유지하면서 Verified Address, Balance, Code 등 새로운 검증 서킷을 확장 적용할 수 있습니다.
